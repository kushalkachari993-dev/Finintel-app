# Render Deployment

This project deploys to Render as two services:

- `finintel-ai-backend`: FastAPI web service
- `finintel-ai-frontend`: React/Vite static site

The root `render.yaml` is a Render Blueprint. It follows Render's current
Blueprint model: web services use `type: web`, Python uses
`runtime: python`, static sites use `runtime: static`, and `/health` is the
backend health check. Both services use `autoDeployTrigger: checksPass`,
so Render deploys only after GitHub Actions checks pass.

## Create The Blueprint

1. Push this repository to GitHub.
2. In Render, choose **New > Blueprint**.
3. Select the repository.
4. Render will detect `render.yaml`.
5. During creation, fill the `sync: false` values.

## Required Backend Environment Values

Set these on `finintel-ai-backend`:

```env
GROQ_API_KEY=...
TAVILY_API_KEY=...
FRONTEND_ALLOWED_ORIGINS=https://your-frontend.onrender.com
```

Set these if Clerk is enabled:

```env
CLERK_JWKS_URL=https://your-clerk-domain/.well-known/jwks.json
CLERK_ISSUER=https://your-clerk-domain
CLERK_AUDIENCE=
```

Optional:

```env
SENTRY_DSN=...
```

`APP_API_KEY` and `AUTH_TOKEN_SECRET` are generated by Render.

## Required Frontend Environment Values

Set these on `finintel-ai-frontend`:

```env
VITE_BACKEND_API_URL=https://your-backend.onrender.com
VITE_CLERK_PUBLISHABLE_KEY=pk_...
```

Optional:

```env
VITE_SENTRY_DSN=...
```

## SQLite On Render Free

The default Blueprint keeps the app free-friendly and uses:

```env
DATABASE_URL=sqlite:///data/finintel.sqlite3
```

This is fine for a demo, but Render free web services have an ephemeral
filesystem. Local SQLite data can be lost when the service redeploys,
restarts, or spins down. For production-grade persistence, move to Render
Postgres, Neon, Supabase, or a paid Render service with a persistent disk.

## After First Deploy

1. Open the backend URL and check `/health`.
2. Copy the frontend URL.
3. Set backend `FRONTEND_ALLOWED_ORIGINS` to the frontend URL.
4. Copy the backend URL.
5. Set frontend `VITE_BACKEND_API_URL` to the backend URL.
6. Redeploy both services.
7. Open the frontend and ask `What is ROE?`.

## Expected Checks

Backend:

```bash
curl https://your-backend.onrender.com/health
```

Expected result:

```json
{"status":"ok"}
```

Frontend:

- Page loads without CORS errors.
- Clerk sign-in opens.
- A brief query sends a request to `/chat/stream`.
- The answer appears in the chat chain.
